jQuery 4.1.0 与 3.8.0——4.x 首个小版本补上 ReDoS 修复，3.x 就此只修关键问题

11 月 17 日同日发布的两个版本：4.1.0 是 4.x 首个小版本，补上了选择器正则回溯修复；3.8.0 是 3.x 最后一个计划功能版本。

有效 11-26 · 晚 高热度 原始来源 ↗

11 月 17 日，jQuery 同时发布了 4.1.0 与 3.8.0。4.1.0 是 4.x 系列的第一个小版本：jqXHR 新增 responseURL，修了选择器正则回溯导致的页面挂起，内部查找改用 querySelectorAll。同日发布的 3.8.0 是 3.x 最后一个计划功能版本，此后只修关键安全与问题修复，官方明确催老用户升级到 4.x。

先看这几点

  • 4.1.0：jqXHR 新增 responseURL，可取重定向后的最终地址
  • 4.1.0：修复选择器正则回溯，避免页面挂起
  • 4.1.0：内部查找改用 querySelectorAll，uniqueSort 提速
  • 3.8.0：3.x 最后一个计划功能版本，此后只修关键安全与问题
  • 官方建议升级到 4.x，附升级指南与 Migrate 插件

两个版本合起来看才有意义：4.1.0 说明 4.x 已进入常规迭代，3.8.0 则是一次正式的交接。最值得注意的是正则回溯修复：选择器里一长串十六进制转义加非法字符可能让页面挂起，这类问题平时遇不到，遇到了就是整页卡死。老项目即使不升级功能，也值得评估这次的安全修复。

适合还在维护 jQuery 项目的前端开发者与技术负责人：新项目直接用 4.1.0；老项目先读升级指南，用 Migrate 插件扫一遍废弃 API，再决定升级节奏。完全不用 jQuery 的团队，这条可以只当作行业动态略读。

怎么用

  1. 先确认当前项目用的 jQuery 版本与 CDN 或 npm 来源
  2. 读官方升级指南，列出项目里用到的废弃 API
  3. 本地装 Migrate 插件跑一遍，看控制台警告
  4. 先升到 3.8.0 验证，再按指南升 4.1.0
  5. 上线前在测试环境跑一遍选择器密集的页面，确认没有回归
别长期留在 3.x

3.8.0 之后 3.x 只修关键问题，新功能与常规修复都不会再有，长期停留在 3.x 意味着与上游渐行渐远。升级前注意：4.x 移除了一些 3.x 已废弃的 API，Migrate 插件能提前报警，别跳过这一步直接换 CDN 链接。

jQuery 的交接做得算体面：给老分支一个收尾版本，给升级留了工具与文档。对老项目来说，这次的动作不是追新功能，而是把升级排进计划，避免哪天一个安全修复只发在 4.x 才想起来。
