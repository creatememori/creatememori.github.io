Pax by Pydantic——官方终端编程 Agent：编码、沙箱、MCP 全是可插拔插件，任意模型随便换

Pydantic 官方出的终端编程 Agent：编码、沙箱、MCP 与观测全是可插拔插件，任意模型随便换，还能直接跑你自己的 Pydantic AI Agent。11 月 25 日发布 Beta，Harness 1.0 约一个月后到来。

有效 11-26 · 晚 高热度 原始来源 ↗

11 月 25 日，Pydantic 正式发布 Pax：官方终端编程 Agent，跑在 Pydantic AI Harness 之上。它的设计只有一句话：一切都是插件。编码、沙箱、MCP、观测全是可插拔的插件，模型也可以随便换；更进一步，--agent 能直接跑你自己的 Pydantic AI Agent，把 Pax 当成你家 Agent 的终端外壳。

先看这几点

  • 编码、沙箱、MCP、Logfire 观测全是插件，在 /plugins 里开关。
  • --agent 直接跑你自己的 Pydantic AI Agent，不用重写终端交互。
  • /sandbox 一行切换云端或本地沙箱，分支与未提交改动自动同步。
  • pax --resume-claude 或 --resume-codex 可导入旧会话继续做。
  • 目前 Beta，Harness 1.0 约一个月后发布，接口仍可能调整。

Pax 背后是 Pydantic AI Harness：一套超过 100 个能力的生产级能力库，编码只是其中一个叫 Coder() 的能力。也就是说，Pax 既是一个能直接干活的终端 Agent，也是一份“用 Harness 能搭出什么”的活样品。官方跑分里，它在 Harness-Bench SWE81 八个模型平均分 58.5，略高于 OpenCode 的 58.2；同一任务在 GPT-6.2 Sol 上花费 9.21 美元，Codex 则要 21.05 美元。不过这些都是 11 月的单次跑分，看看就好，不必当成定论。

最适合已经在用 Pydantic AI 写 Agent 的人：你在代码里调好的 Agent，不用再套一层终端界面，直接交给 Pax 跑。想在多个模型之间横向对比、或想把沙箱执行收进自己流程的团队也可以试。只想找个开箱即用的写代码助手、又不想折腾插件的人，Claude Code 或 Codex 可能更省事。

怎么用

  1. 装好 uv 后跑 uvx pydantic-ai-pax，不用安装就能试；常驻则用 uv tool install pydantic-ai-pax。
  2. 进 /plugins 看一眼默认开着哪些插件，不需要的先关掉。
  3. 先在小仓库里跑一个真实任务，确认模型、沙箱与观测都按预期工作。
  4. 满意后再用 --agent 接入自己的 Agent，或把常用配置写进项目。
别忽略这一条

三点注意：现在是 Beta，公开接口可能在 1.0 前调整；模型费用自理，多模型并行试错时先看账单；macOS 自带一个同名的 /bin/pax 归档工具，装完若启动的不是 Pax，换个新终端或直接跑 pydantic-ai-pax。另外，Harness 的断点续跑能力目前还没进 Pax。
