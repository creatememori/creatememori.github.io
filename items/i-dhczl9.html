State of HTML 2026——2,091 名开发者调查：details/dialog 成标配，表单控件仍是最痛

10 月 1 日至 11 月 1 日、2,091 名开发者参与的调查：details 与 dialog 已成日常工具，表单控件仍是大家最痛的地方。

有效 11-26 · 晚 高热度 原始来源 ↗

State of HTML 2026 在 11 月 15 日发布结果，调查在 10 月 1 日至 11 月 1 日进行，收到 2,091 名开发者的回答。结论很清晰：details 与 summary 用到 72.5%，dialog 用到 67.8%，Popover API 用到 40%，原生 HTML 元素正在接管过去要靠 JavaScript 实现的功能；而表单控件仍是最大痛点，select 与日期输入最难定制。

先看这几点

  • details 与 summary 使用率 72.5%，dialog 使用率 67.8%
  • Popover API 使用率 40%，已进入日常工具箱
  • 表单控件是最大痛点，select 与日期输入最难定制
  • 可定制 select 被浏览器支持卡住，Firefox 尚未发布
  • 最想要的缺失元素是原生可排序与筛选的数据表格
  • AI 生成代码占比中位数 50%

这份调查的价值不在排名，而在趋势：浏览器厂商终于开始成体系地补原生能力，dialog、popover、details 这些元素一旦成为标配，很多轻量交互就不需要再引入组件库。对做前端选型的人来说，它回答了一个实际问题：下一个项目里，哪些交互可以直接用原生元素写，哪些还得继续靠库。

适合前端开发者、技术负责人与做组件库的人：正在评估要不要去掉某个界面依赖，或者纠结表单定制方案时，这份数据能帮你判断主流做法。学生与转行者也可以从中看到，现在的前端日常工具箱长什么样。

怎么读

  1. 打开 2026.stateofhtml.com，按章节浏览
  2. 先看 Features 与 Pain Points 两部分，对照自己项目的现状
  3. 把 details、dialog、popover 的使用率与团队的浏览器支持基线对照
  4. 再看最想要的缺失元素一节，判断哪些需求现在只能靠库
  5. 把结论记进团队的技术选型笔记，而不是只看个热闹
样本说明

样本只有 2,091 人，且是主动参与调查的开发者，数据反映的是关注前沿的群体，不等于全行业平均水平。AI 生成代码占比中位数 50% 同样来自受访者自报，读的时候当作趋势信号，别当成精确统计。

调查本身也在讲一个更大的变化：AI 生成代码越来越常直接调用浏览器 API，而不是套框架。把这份结果当作一次盘点：哪些原生能力已经可以进你的项目，哪些痛点还得等浏览器厂商下一步。
