VS Code 1.148——Agent 优先版：对话提速约 30%、防休眠让无人值守 Agent 接着干

11 月 25 日发布的 Agent 优先版：Agent Host 对话开始响应平均快约 30%，新设置可防止机器在 Agent 工作时闲置休眠。

有效 11-26 · 晚 高热度 原始来源 ↗

VS Code 1.148 在 11 月 25 日发布，整版围绕一个场景：让 Agent 无人值守接着干。Agent Host 对话开始响应平均快约 30%，新设置 sessions.keepAwakeWhileWorking 能防止机器在 Agent 工作时闲置休眠，远程 worktree 一键清理，还加入了实验性的 Dev Container 与沙箱配置。

先看这几点

  • Agent Host 对话开始响应平均快约 30%
  • 新设置 sessions.keepAwakeWhileWorking，防闲置休眠
  • 远程 worktree 一键清理，回收废弃工作区的磁盘
  • 实验性 Dev Container 与沙箱配置
  • Rust diff 中位数提速 2 倍多，CLI 缩小约 40%
  • Local harness 已弃用，2027 年 2 月移除

Agent 从助手变成值夜班的同事后，编辑器的瓶颈变了：以前是补全准不准，现在是人走开后任务会不会中途停掉。对话提速解决的是等待感，防休眠解决的是任务半夜被系统睡眠打断，worktree 清理解决的是远程机器被废弃工作区占满磁盘。这三件事都不花哨，但直接决定了无人值守流程能不能跑通。

适合已经把 Agent 接进日常开发的人：下班前派一串任务、早上回来验收，或者在远程机器上长期跑 Agent 会话的开发者。只用 VS Code 写代码、还没用 Agent 功能的人，这版的变化感知不会太强，可以等常规更新。

怎么用

  1. 更新到 1.148，打开设置搜 keepAwakeWhileWorking，按需选 whenPluggedIn 或 always
  2. 在 Agents 窗口里试一次长任务，观察对话开始响应是否变快
  3. 用 Chat: Open Worktree Cleanup 清理远程主机上的旧工作区
  4. 需要隔离环境时试实验性的 Dev Container 配置
  5. 留意 Local harness 将在 2027 年 2 月移除，提前迁移到 Agent Host
数字与实验性

30%、2 倍多、40% 这些数字都是官方口径，实际体感因项目大小而异。防休眠默认只在接通电源时生效，笔记本用电池跑长任务要显式改成 always。Dev Container 与沙箱配置仍是实验性，生产流程先别完全依赖它们。

这是一次方向很明确的版本：编辑器的主角正在从人变成 Agent。升级成本很低，先开防休眠与 worktree 清理这两个最稳的改进，实验性功能等下一个版本再评估。
