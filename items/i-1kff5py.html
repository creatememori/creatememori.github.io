Vercel MCP 现在能管 AI Gateway——用一句话建虚拟模型、改路由规则、定花钱上限

接上 Vercel MCP 的 Agent 现在能直接管 AI Gateway：一句话建虚拟模型、改路由规则、给团队定花钱上限。

有效 11-28 · 早 高热度 原始来源 ↗

11 月 24 日的官方 Changelog 宣布，接上 Vercel MCP 的 Agent 现在可以直接管理 AI Gateway：创建带固定配置的可复用模型 ID、增改团队级路由重写与拦截规则、设置团队、项目与成员四档支出预算。改模型配置不用改客户端，也不用重新部署，一句话就能让 Agent 去办。这对把多个模型接进同一套服务的团队来说，等于把模型管理从代码发布流程里抽了出来。

先看这几点

  • 可创建带固定配置的可复用模型 ID，改配置不用改客户端、不用重新部署。
  • 能增改团队级路由重写与拦截规则，设置四档支出预算。
  • 须团队级接入与 AI Gateway 权限，现有团队权限仍是边界。

它的价值在两处：一是配置与代码解耦，换模型、调参数不再需要走一次发布；二是成本有了明确的上限，团队、项目和成员四档预算可以分开管，某个人或某个项目跑超了也不会把整个团队的账单拖垮。虚拟模型 ID 的做法也值得留意：调用方只认一个固定 ID，后面实际用哪个模型由网关决定，切换模型时调用方完全不用动。

适合已经在 Vercel 上跑 AI 功能、并且由团队共同维护的项目，尤其是模型调用量大、需要分人分项目控制成本的场景。个人项目或还没接 AI Gateway 的团队暂时用不上。公告里没有提到逐项人工确认的步骤，所以授权时要按人来管：只给需要的人开权限，不要把网关管理权限当成默认配置发下去。

怎么用

  1. 确认团队已接入 AI Gateway，并给 Agent 配好团队级权限。
  2. 让 Agent 创建虚拟模型 ID，并设置好路由规则与四档预算。
  3. 先在小范围验证一次改动，再推广到全团队的调用方。
别忽略这一条

权限边界要先想清楚：须团队级接入与 AI Gateway 权限，现有团队权限仍是边界；公告未提逐项人工确认步骤，授权时按人来管。把能改路由和预算的权限交给 Agent 之前，先确认哪些人可以触发这些操作。
